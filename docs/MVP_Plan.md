MVP计划

* 每个Agent集群有一个对外的Gateway openclaw，为了和openclaw自己的gateway区分开，我把某个集群中的这台EC2叫做“阿G”



1\. 购买一个域名（比如从GoDaddy），DNS 选一家托管（安全点比如Cloudflare）

2\. 创建 AWS 账号

\-------------------------------------------------------------------------------

3\. 开 1 台入口 EC2，绑定 Elastic IP，部署 Nginx（不建议使用外部的服务器来host，都放在AWS里安全更可控）

4\. 开 2 台 阿G EC2，部署同版本 Linux 和 OpenClaw，一台用于开发（称作Dev），一台用于测试部署（称作Test），暂时不引入集群（等到后端好了再加）

5\. 在入口机配置 `www` 和 `app` 两个入口

\-------------------------------------------------------------------------------

6\. `www` 指向产品宣传页

\-------------------------------------------------------------------------------

7\. `app` 后面接一层薄认证 / 路由服务

8\. 使用登录服务接 Google 登录/邮箱登录（可选的比如Supabase或者AWS自家的Cognito，Supabase可能更方便），并设置一个测试用户（称作Tom）

9\. 登录后先进入入口机上的账户页，不直接进入 阿G

10\. 账户页按 email 判断用户是否有权限访问某台 阿G

11\. 账户页显示：

&#x20;  - 当前用户身份

&#x20;  - 是否已开通服务

&#x20;  - 订阅信息/账单

&#x20;  - 进入自己 Gate Dashboard 的按钮（访问app.example.com/dashboard，Nginx把请求反代到对应的阿G的10.x.x.x:3000端口的Dashboard服务）

&#x20;  - 等等等等

\--------------------------------------------------------------------------------

12\. 在 Dev 这个阿G上开发 中台Dashboard

13\. Dashboard 读取本机 OpenClaw 的：

&#x20;  - health

&#x20;  - sessions

&#x20;  - skills

&#x20;  - 指定 md 文件

14\. 第一版 Dashboard 支持：

&#x20;  - 查看 Agent 状态

&#x20;  - 查看 Session 列表和内容

&#x20;  - 查看和编辑 Skills

&#x20;  - 查看和编辑指定 md 文件

\---------------------------------------------------------------------------------

15\. 在 Test 阿G 上部署 Dashboard，监听 `3000`

16\. 只允许入口机访问 阿G 的 `3000`，OpenClaw 不直接暴露到公网

17\. 通过 `app` 登录验证：

&#x20;  - 未购买用户只能停留在账户页

&#x20;  - 已授权用户可以进入自己的 阿G （测试期就是：测试用户Tom可以访问Test）的Gate Dashboard

&#x20;  - 能看到/修改自己的 阿G 上的 OpenClaw 状态

\---------------------------------------------------------------------------------

18\. 上面是 MVP，跑通后，再做CICD：

&#x20;     - 在账户页有“创建”按钮

&#x20;  - 自动创建 EC2

&#x20;  - 自动部署Linux、Openclaw 和 Dashboard

&#x20;  - 自动配置入口路由

&#x20;  - 购买后自动开集群（等后端接口好了）

&#x20;     - 测试用户Tom可以新建集群并访问对应集群的 阿G 的Dashboard

\---------------------------------------------------------------------------------

19\. 再往后再考虑：

&#x20;  - ALB替代Elastic IP

&#x20;  - 计费系统、服务与Stripe等

&#x20;  - 完整的订阅信息数据库

&#x20;  - 多租户自动化管理

&#x20;     - 内部的后台成本监控等
